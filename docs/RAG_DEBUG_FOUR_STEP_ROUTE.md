# 四阶段Bad Case审计

1. **召回**：在全文定位正确公司、年度、指标与精确数值，判断候选集是否包含必需输入。
2. **重排**：比较原候选与Top10，检查是否丢失必需证据；使用计算需求覆盖保护。
3. **Prompt与上下文**：检查表头、年份、单位、引用编号及当前输入需求是否清晰投递。
4. **生成与工具**：检查公式依赖、字段绑定、来源引用、单位归一化和错误反馈；区分模型错误与校验器误拦。

每题保留问题、候选排序、实际上下文、计划、绑定和工具事件，不能仅凭最终错误答案归因为模型知识不足。
修复后使用相同模型／精度／冻结输入做配对回归。运行与计分见[运行指南](QUICKSTART.md)，指标见[评测说明](EVALUATION.md)。
